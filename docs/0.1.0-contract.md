# STAK 0.1.0 — Signed-in Product Contract (P0)

Status: **P0 — contract & model closure** (docs/spec only; no schema, no CLI, no UI).
This is the engineering contract that every later phase (P1–P10) builds against. Where
the design and this contract disagree, **this contract wins on data/architecture; the
design wins on UI, copy and hierarchy** (per the implementation brief). It contains no
per-project Memory mode, no unresolved VERIFY item, and none of the removed commands.

Sources reconciled: the final design contract (`STAK Final Contract.dc.html`, imported via
the design MCP — requires `/design-login`; read before P4) and the **STAK 0.1.0 Product
Contract Audit**. Everything below is already true in code unless marked **NEW**.

---

## 0. Non-negotiable invariants (hold in every phase)

- Preserve the frozen Memory crypto/format constants (`stack-project-compat-v1`,
  `stack-mem-remote-v1`, `stack-mem-bundle-v1`, `stack-mem-cipher-v1`,
  `stack-mem-bridge-v1`, `stack-memory-recovery-v1`, `stack-memory-passkey-v1`,
  `stack-memory-bridge-v1`, `stack-mem-device-mmk-v1`, `stack-memory-recovery-file-v1`),
  `.stackkey`, Project IDs, legacy `~/.stack` adoption, `STAK_*`/`STACK_*` env
  compatibility, every existing backup, local-only project bindings, and Standard/Protected
  semantics.
- Memory privacy mode is **account-wide**. Never model, store, or display a per-project mode.
- Check-in **never** uploads absolute local paths, **never** a home-relative locator (see
  §3 ENG DECISION), and **never** raw Memory content. Protected Memory stays ciphertext
  server-side and is never readable by Cloud.
- **No daemon, no background sync.** State changes only during CLI operations the user runs.
- **Never mutate a remote machine.** Web actions write account-side _desired_ state only;
  machines realise it on their next CLI run.
- Capabilities come from **declared metadata only**; when absent, show "Capabilities not
  declared". Never infer permissions from prose or skill bodies.
- Updates **fail closed**: Local/dirty/unreachable sources show "Can't check for updates
  from this source", never "Update available".

### Commands

Use existing commands exactly where they exist. **Build only** these new commands:
`stak skill update [<skill>]`, `stak skill pause <skill>`, `stak skill resume <skill>`,
`stak open`. **Extend** `stak status` to also perform the explicit check-in without
breaking its current local-readiness output.

These must **never appear anywhere**: `stak restore`, `stak stack apply`,
`stak project locate`.

**FUTURE (do not build in 0.1.0):** "Turn into a Skill", per-project stack apply, remote
machine actions, static analysis of skill bodies, public-stack usage counts, a general
activity/events table.

## 1. Memory model (account-wide)

- Privacy mode lives on `MemoryProfile.privacyMode` ∈ {`standard`, `protected`} — **one per
  account**. A backup is wholly Standard or Protected; `stak memory protect` migrates all
  existing generations. Manifest items have no mode.
- **Standard** — "Backed up": `mode = standard AND last_backup exists`. Private to your
  account; STAK's service can read it to deliver it. Don't say "encrypted"/"only you".
- **Protected** — "Protected": `mode = protected AND last_backup exists`. Encrypted on your
  machine before upload; Cloud stores only ciphertext and can't read it. Don't say "safe
  (alone)"/"synced".
- **Not backed up yet**: `last_backup is null`.
- UI: a single account-wide mode banner. A per-project **table is allowed** (files, last
  backup, last change — all derivable from the manifest) but **must not** carry a mode/
  "KEPT AS" column, and Settings must not offer a per-project mode. "New projects keep
  Memory as…" / "change per project" copy is removed.

## 2. Recover → Restore → Map (the new-machine sequence)

Two distinct real commands; **never** a root `stak restore`:

- `stak memory recover` — Cloud → this machine's **private STAK store** (`~/.stak/memory/`).
  Protected requires a passkey (browser) or recovery file. Does not touch agent files.
- `stak memory restore` — private store → **native agent Memory files**; writes only absent
  targets (never overwrites), gated by project availability/mapping.

A brand-new machine: `install CLI → stak login (approve) → stak memory recover
(+ passkey/recovery file if Protected) → stak memory restore → stak project map <unavailable
projects>`. The web presents **one guided "Bring your STAK here" outcome** that sequences and
_shows_ these real commands (web cannot run them); both terms stay visible because they mean
different things.

## 3. Machine check-in model (**NEW**)

No daemon. The CLI reports machine state **best-effort** during user-run operations.

**Payload (V0):** `machine_id`, friendly `name`, `platform`, `arch`, `agents_detected[]`,
`last_checkin`, `skills: [{ skillId, installed_version }]`, `projects: [{ projectId,
present: boolean }]`.

**Privacy rules (hard):**

- **No absolute paths. No home-relative path either.** Project state is **presence only**.
- No raw Memory content. Protected payloads never decrypted server-side.
- No credentials in errors.

**ENG DECISION — home-relative project locator: RESOLVED = do not ship.** STAK 0.1.0 Cloud
does **not** persist any project path/locator (absolute or home-relative). Check-in reports
presence only. The viewing machine may read its own local path locally where needed, but
Cloud never stores or returns it. (Addendum §5.)

**Triggers** (emit after the operation succeeds, where machine state materially changes):
`login`, `status` (the explicit check-in), `memory backup`, `memory recover`,
`memory restore`, `use`, `run`, `scan`, `project map`, `skill update`, `skill pause`,
`skill resume`. Audit `push`/`pull`/`remove` and add check-in only where resulting machine
state materially changes.

**Failure semantics (Addendum §2):**

- Connectivity failure (network unreachable, timeout, temporary 5xx) → **non-fatal**; the
  parent local operation continues where safe; check-in is skipped silently.
- Explicit **401/403** → **not** treated as offline; surfaced distinctly. A revoked/invalid
  machine must never appear successfully checked in.

**Derived states (read model, not stored as truth):**

- _Up to date_ — at last check-in every Ready skill's installed version matched STAK's
  approved version AND Memory was backed up. Always shown with the check-in time.
- _Updates waiting_ — any approved skill version differs from the machine's installed
  version at last check-in.
- _Last seen \<time\>_ — `last_checkin`. Never "online/offline".

## 4. Stacks: `stak use <stack>` composes into `main`

`stak use <stack>` is "apply a stack" and composes into the **`main` environment** (not a
per-project folder). Keep `stack.yaml`, `extends`, the resolver, conflict planning, and the
existing **dry-run preview** (`stak use <stack> --dry-run` prints the plan). Public stacks
and inspect-before-use exist. The design's "apply to \<project\>" is reframed as composing
into `main`; per-project apply is **FUTURE**. `stak stack apply` must never appear.

## 5. Skill update model (source / desired / installed)

Three versions:

- **source** — the exact **immutable revision** the tracked Git ref (or public-stack/package
  version) currently resolves to.
- **desired (approved)** — the version approved in STAK; approving creates a **new imported
  version**, account-side only. Never touches a machine.
- **installed** — per-machine, reported at check-in.

Rules:

- _Update available_ (Git source) = tracked ref resolves to a **different exact revision**
  than the approved one. **Identity comparison** of resolved revisions — never lexical or
  numeric comparison of hashes (Addendum §4). Public-stack/package sources use that source's
  real version semantics.
- **Fail closed** for Local, dirty, ambiguous, or unreachable sources: "Can't check for
  updates from this source"; never a false "Update available".
- `stak skill update [<skill>]` installs approved versions **on this machine** and reports
  failures at check-in. Web approval only sets desired state; each machine installs on its
  next CLI run. "Update failed on \<machine\>" surfaces from that machine's next check-in.

## 6. Pause semantics

- A per-skill `paused: boolean` (default `false`; absent = active) is machine-local desired
  state carried in the lock. Retains version/provenance — **do not overload `remove`**.
- Resolver: a paused skill stays in STAK and the lock but is **excluded from agent
  projection**; `stak run` skips it. `stak skill resume` clears it.
- Desired `paused` may ride the pushed environment so the web can show it; per-machine effect
  is realised on next `run`. Migration: lock files from before this field still load.

## 7. Declared-capability field (optional)

- Capabilities (Read files / Write files / Run commands / Network) come from an **optional
  declared block in SKILL.md** only. Absent → UI shows "Capabilities not declared".
- V0 = source/trust info + declared capabilities when present. **No static analysis** of
  skill bodies (FUTURE). Never infer permissions from prose. "Asks for nothing new" means no
  declared-capability delta between approved and source versions.

## 8. Activity derivation (no events table)

Activity is **derived only** from existing records / deliberately-stored change timestamps —
**no general events table** (FUTURE):

- Memory backed up ← `memory_backups.created_at`
- Machine checked in ← `last_checkin`
- Update approved ← new imported version
- Project mapped / presence change ← check-in presence deltas
- Stack published ← `public_stack_versions`

**Truthfulness (Addendum §7):** never fabricate a historical event from a current-state
timestamp. If an activity type cannot be truthfully reconstructed from a real record or a
deliberately-stored change timestamp, **omit it** for 0.1.0.

## 9. Delete cloud Memory (**NEW**, destructive — narrow)

"Delete cloud Memory" deletes **STAK's server-held Memory backup data for the account** —
the Cloud backup payloads/metadata required to recover those Cloud copies. (Addendum §6.)

It **MUST NOT** delete: native agent Memory files, the local private STAK Memory store,
Skills, Projects, machine-local bindings, the STAK account; and it must **not** be confused
with project archive (archive never deletes).

**Recovery-method consequence (specify + test before building):** once Cloud backup payloads
are deleted, Protected recovery wrappers (`memory_recovery_methods`) that exist only to unlock
those Cloud copies become useless. Determine per-record whether they are invalidated or
removed as a consequence; document and test that behaviour in P3/P8 before implementation.
UI: typed-confirmation hard delete, worded that **local Memory is untouched but Cloud
recovery will no longer be available**.

## 10. Frozen language (customer-facing)

- **Skill:** Ready · Update available · Paused (+ note "Can't check for updates from this
  source").
- **Memory:** Backed up · Not backed up yet. Mode: Standard / Protected (account-wide).
- **Machine:** Up to date · Updates waiting · Last seen \<time\>.
- **Project:** Active · Archived · On this machine · Not on this machine.
- **General:** Needs attention.
- **Banned for normal states:** In sync, Online, Offline, Outdated, Lost, Broken, Unsafe.
  Each word appears only when its data condition holds; "Up to date" always with its
  check-in time.

**Needs attention** = union of: an update to review; a project not on the viewing machine; a
machine not seen in 30+ days; Protected Memory with no recovery method. Amber, never red
unless something actually failed.

## 11. Recovery naming

Recovery is a **recovery file** (`.stackkey`) or a **passkey** — not a typed "recovery key".
Design copy that says "recovery key" is renamed accordingly. The account-wide mode is
switched via `stak memory protect`.
